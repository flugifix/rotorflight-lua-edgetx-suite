# RFSuite Sensor Integration

## Overview

Centralized telemetry sensor management for both hardware and simulation environments.

**Key Files:**
- `src/rfsuite/lib/sensors.lua` — Central sensor definitions & alias mapping
- `bin/sensors/sensors.xml` — Sensor tool configuration  
- `bin/sensors/src/sensors.py` — Simulator-aware telemetry tool
- `.vscode/tasks.json` — Build & run tasks

---

## Architecture

### 1. **Sensor Definition** (`src/rfsuite/lib/sensors.lua`)

All sensors use the 4-character RF2 naming convention (e.g., `Vbat`, `Hspd`, `Thr%`).

**Aliasing System:**
```lua
Sensors.aliases = {
  voltage = "Vbat",
  rpm = "Hspd",
  fuel = "Bat%",
  -- ...
}
```

Dashboard sources can use either:
- 4-char name: `source = "Vbat"`
- Alias: `source = "voltage"`

Both resolve to the same underlying sensor.

### 2. **Resolution Priority** (`objects/common.lua`)

When `mapTelemetrySource(source, state)` is called:

1. **Simulator**: Try 4-char name via `getValue()` (Sensor Tool writes these)
2. **Hardware**: Try direct `getValue(source)` if 4-char exists
3. **Fallback**: Legacy state mapping for backwards compatibility

```lua
-- Example: source = "voltage"
-- → Sensors.resolveName("voltage") = "Vbat"
-- → getValue("Vbat") = 24.2
```

### 3. **Sensor Tool** (`bin/sensors/`)

Python/PyInstaller-based GUI for simulator telemetry.

**Features:**
- Auto-discovers simulator targets
- Writes per-sensor Lua files to `simulator/<target>/scripts/rfsuite/sim/sensors/`
- Simulator detection: checks if `EDGETX_SIMULATOR` env var is set
- Supports range sliders, select dropdowns, random variance

**Supported Sensors** (from `sensors.xml`):
- Flight Control: `ARM`, `Gov`, `Hspd`
- Power: `Vbat`, `Vbec`, `Curr`, `Capa`, `Bat%`
- Profiles: `PID#`, `RTE#`, `BatP`
- Temps: `TescT`, `TmcuT`
- Dynamics: `Ptch`, `Roll`, `Yaw`

## Usage

### Building the Sensor Tool

```bash
cd bin/sensors/src
make.cmd
```

Produces: `bin/sensors/sensors.exe`

### Running via VS Code

Three tasks available:

1. **`Sensors: Build Tool`** — Builds `sensors.exe` from Python
2. **`Sensors: Run Tool`** — Launches the telemetry editor GUI
3. **`Sensors: Build + Run Tool`** — Builds + launches in sequence

From VS Code Task Menu → Select "Sensors: Build + Run Tool"

### Manual Editing Sensors

Each sensor is a simple Lua file in `simulator/<target>/scripts/rfsuite/sim/sensors/`:

```lua
-- Vbat.lua (generated by sensor tool)
return 24.2
```

Edit manually or use the GUI tool.

## Dashboard Integration

### Using Sensors in Widgets

```lua
-- preflight.lua theme
{
  col = 9, row = 1, colspan = 12, rowspan = 8,
  type = "gauge", subtype = "arc",
  source = "voltage",           -- Or use "Vbat" directly
  title = "@i18n(widgets.dashboard.voltage)@",
  -- ...
}
```

### Widget Runtime Flow

1. Theme defines `source = "voltage"` (alias)
2. Engine calls `mapTelemetrySource("voltage", state)`
3. Sensor module resolves `"voltage"` → `"Vbat"`
4. Widget calls `getValue("Vbat")` (simulator writes this value)
5. Arc gauge updates

## Simulator Detection

Check if running in simulator:

```lua
local Sensors = assert(loadScript(".../lib/sensors.lua", "t"))()
if Sensors.isSimulator() then
  -- Load simulator-specific code
else
  -- Hardware path
end
```

**Detection Method:**
```lua
function Sensors.isSimulator()
  local fw = select(2, getVersion()) or ""
  return string.sub(fw, -4) == "simu"
end
```

## Extending Sensors

To add a new sensor:

1. **Edit** `src/rfsuite/lib/sensors.lua`:
   ```lua
   Sensors.map = {
     MyS4 = { label = "My Sensor", unit = "X", prec = 0, fallback = 0 },
     -- ...
   }
   ```

2. **Edit** `bin/sensors/sensors.xml`:
   ```xml
   <Sensor name="MyS4" label="My Sensor" type="range" min="0" max="100" />
   ```

3. **Deploy**: `RFSuite: Deploy to Simulator` task

4. **Run sensor tool**: `Sensors: Build + Run Tool` → adjust slider → Save

## Hardware (No Simulator)

On actual hardware:
- Sensors module still loads (lightweight, ~2KB)
- Simulator detection returns `false`
- `getValue()` reads real telemetry from radio hardware
- Sensor Tool GUI code is **never executed**

No payload penalty on device.

---

## Backwards Compatibility

Old dashboard themes using internal state names continue to work:

```lua
source = "rpm"           -- Still works (alias → "Hspd")
source = "pid_profile"   -- Still works (falls back to state.profile)
```

Recommendation: Migrate to 4-char names for new code.

## Troubleshooting

**Sensor Tool won't start?**
- Ensure PyInstaller is installed: `pip install pyinstaller`
- Run `Sensors: Build Tool` first to rebuild `.exe`

**Sensors not updating in simulator?**
- Check: Is `EDGETX_SIMULATOR` env var set?
- Verify: Files exist in `simulator/<target>/scripts/rfsuite/sim/sensors/`
- Check console for errors in Tool UI

**Widget shows `--` (no data)?**
- Check sensor source name matches `sensors.lua` map
- Verify sensor file exists and contains a valid Lua return value
- Check `mapTelemetrySource()` resolution logic
