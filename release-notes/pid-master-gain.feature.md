- **Cyclic and yaw master gains (`tasks/msp/api/pid_profile.lua`, `app/pages/flight_tuning/advanced/pid_controller/`, `app/pages/setup/controls/adjustments/page.lua`, `widgets/dashboard/inflight/functions.lua`, `tasks/events/telemetry_bg/adjustments.lua`, `tasks/msp/runtime.lua`, `docs/pages/flight_tuning/advanced/pid_controller.md`, `docs/pages/setup/controls/adjustments.md`)**:
  - The suite side of rotorflight/rotorflight-firmware#538. *PID Controller* has a *Master Gain* row (Cyclic / Yaw, 25 to 200 %, default 100 %): Cyclic scales the roll and pitch P, I, D and Offset gains together, Yaw the tail P, I and D gains, keeping their ratios; Feedforward, Boost and the precompensations are not scaled.
  - *Adjustments* offers *Cyclic Master Gain* (83) and *Yaw Master Gain* (84), announced as "cyclic gain" and "yaw gain". The in-flight tuning overlay names both, primes them from the PID profile read it already makes, and drops them on a PID profile switch like the other per-profile values.
  - #538 did not change the MSP API version, so availability comes from the PID profile reply: every parse records whether it carried the two gains, and a disconnect clears that. The row, its help line, functions 83 and 84 and the write of the two gains all go by it, so gains left in the shared PID profile table by an earlier board are neither shown nor sent. On MSP API 12.10, *Adjustments* reads the PID profile once when nothing has yet on this connection.
  - A firmware without the gains is unchanged: its PID profile reply (43 bytes on MSP API 12.9, 44 bytes on 12.10) is written back byte for byte, including the Error Decay Stick Gain, from every page that saves this profile.
