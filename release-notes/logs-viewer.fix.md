- **Logs list and graph are faster and survive the instruction limit (`app/pages/logs/page.lua`, `app/pages/logs/graph.lua`)**:
  - Logs list appears on a card with many logs in the tool opened from the dashboard: sorting the found logs no longer runs a Lua comparison per pair in one call, which the radio stopped from a few hundred logs on, so the list never appeared. The records are sorted by one string each in C and put in order in steps (#607).
  - Logs list search takes one step per folder entry: the search read every name of a folder first and went through the names a second time. Each name is now handled as it is read, which roughly halves the steps of the search in the tool opened from the dashboard, and the folder's names are no longer held while it is searched (#966).
  - Logs loading bar follows the reading of the log: the bar of the summary's and the plot's loading notice was handed a number once and stayed at 0 % until the log had been read. It now reads the engine's position on every refresh (#962).
  - Logs graph shows the loading notice whenever it reads the log: a new curve choice, another flight, and a zoom or page step to a window not read yet showed the old traces with a percentage beside the time range while the file was read; the plot now gives way to the loading notice and its bar for every read.
  - Logs graph opens again without re-reading the log: back from the plot released the engine and its index, so the next *Graph* read the whole file again; it now drops only the plot's data and keeps the index until the page leaves the file. *Show* with the curves already plotted no longer reads the flight again (#961).
  - Logs graph pages a zoomed plot by reading only the new half: a page step moved the window by half its width but read the whole new window from the file. Where the window on screen was read at the screen's resolution, the part both windows share is now copied from it and only the newly shown part is read (#967).
  - Logs graph plots every chosen column when one is chosen twice: the same column in two curve slots left that curve and every later one empty. A repeated column is now plotted once and the other curves are drawn (#963).
  - Logs graph recovers from interrupted curve changes: an instruction-limit stop while changing curves or finishing an extraction no longer leaves the graph raising errors on every pass. Choosing the same curves again restarts an interrupted change (#794).
  - Logs handle a clock set back and a log across midnight: a flight logged after the radio's clock was set back, in the same file, was offered but plotted empty; each flight is now read from its own part of the file. A log that runs past midnight showed a flight time guessed from the row count; it now counts on into the next day (#970).
  - Logs graph no longer keeps a window it read incompletely: in the tool opened from the dashboard, a read stopped at the instruction limit can miss rows. Such a window was kept in the bucket cache and served every later zoom or pan into it with those rows missing; it is now drawn once and read again when needed (#973).
  - Logs reading no longer counts a row twice after an interrupted step: in the tool opened from the dashboard, a step stopped at the instruction limit while the next part of the log was put in place could hand the previous part's rows on again, so a summary counted rows twice. The read position and its data are now replaced so that a stop leaves no stale data behind (#971).
