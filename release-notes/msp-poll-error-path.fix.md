- **A raising MSP poll no longer holds the request queue (`tasks/msp/queue.lua`, `tasks/msp/service.lua`)**:
  - When `common.pollReply` raised, `Queue:processQueue` logged and returned before its retry and give-up logic, so while the transport kept raising the current request was neither sent again nor given up, its `errorHandler` never ran and every request behind it waited. A raising poll now counts as a poll that brought no reply: a read is retried and given up as on a silent board, a write that has already gone out is not sent again but given up at once through its `errorHandler` (unless it completes on silence, as the reboot does once it has been sent twice), and the queue moves on. The warning now carries the error text. No path on the current transports is known to raise there; healthy polling costs two instructions more per call (#772).
