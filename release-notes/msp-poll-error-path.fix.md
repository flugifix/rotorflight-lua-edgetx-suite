- **A raising MSP poll no longer holds the request queue (`tasks/msp/queue.lua`, `tasks/msp/service.lua`)**:
  - When `common.pollReply` raised, `Queue:processQueue` logged and returned before its retry and give-up logic, so while the transport kept raising the current request was neither sent again nor given up, its `errorHandler` never ran and every request behind it waited. A raising poll now counts as a poll that brought no reply: a read is retried and given up as on a silent board; a write already handed to the transport is not sent again, but its current reply window is still waited out, so a reply in that window completes it and otherwise it is given up through its `errorHandler` when the window has passed; a write that completes on silence (the reboot) keeps its retries as on a silent board. The queue then moves on. The warning now carries the error text. No path on the current transports is known to raise there; healthy polling costs two instructions more per call (#772).
