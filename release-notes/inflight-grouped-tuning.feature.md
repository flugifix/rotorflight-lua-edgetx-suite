- **In-flight tuning is grouped by axis and subsystem, tunes every reachable profile, and offers only what the flight controller carries (`widgets/dashboard/inflight`, `tasks/events/telemetry_bg/adjustments.lua`, `app/pages/settings/dashboard/inflight/page.lua`, `app/pages/setup/controls/inflight/page.lua`, `audio/<lang>/inflight/`, `bin/sound-generator/json/`, `docs/dashboard/inflight-tuning.md`, `docs/pages/settings/dashboard/inflight.md`, `docs/pages/setup/controls/inflight.md`, `docs/audio/events.md`)**:
  - The functions are grouped by axis and subsystem (Cyclic, Roll, Pitch, Yaw, Governor, Rates, Filter, Cross Coupling, Rescue and Level, Acc Trim, Other) and carry the Rotorflight Configurator's own names in each language, on screen and in speech; each function and group is spoken from one recording of exactly that name. Tapping the group title opens a menu of every group; the arrows, and PAGE in value mode, walk the functions of the group, PAGE in browse changes the group; the ends do not wrap and play a tone, independent of the adjustment announcement preference.
  - The set is always derived on the ground read from the board's own adjustment slots, so a slot holding another function can no longer be stepped under a different name; nothing is offered before that read. *Set up the flight controller* still writes the standard layout, now with each parameter's full range instead of 10 to 200 (a rescue hover collective of 600 fell to 200 on the first press); the *Set layout* setting is gone. A value outside its slot's minimum and maximum refuses its step.
  - Every PID and rate profile the profile switch can reach is read on the ground and its start values are stored per model on the SD card, bound to the flight controller they were read from. Tuning continues across profile changes in the air; an unread profile refuses steps. *Restore* writes back per profile or all at once, keeps untracked fields, saves once and reads back; every read and restore returns to the original profile pair and waits while armed or disconnected. The post-flight comparison is grouped by profile and group.
  - A new ground surface: three status lines (model, flight-controller slots, session), **Choose parameters** as the primary action (a ticked group list; *Apply* for this session, *Save default* also as the model's flight list), *Read again*, *Reset start values* (asks first) and *Restore all* set apart. Read and restore show one progress screen with a step count.
  - In the air there is no Close and RTN only leaves value mode; every flight starts at the first function of the first group. Value mode shows the value on the left and the plus/minus step targets stacked on the right. The encoder walks a list that is rebuilt before it runs out, so it can no longer reach the touch controls and change the selected function.
  - New spoken states under the adjustment announcement setting: tuning paused on an unread or unknown profile, resumed, selected. Paused/resumed cues play only in flight; profile numbers are announced once, with the general PID/rate event taking ownership when enabled.
  - Trims are off by default for everyone; pilots who tuned with the trims turn them on again in the settings.
  - Always-active adjustment slots are checked in every bank, so an overlapping pulse refuses the affected step direction. Ground reads accept PID gains and rescue altitude P/I/D gains up to the firmware limit of 1000 and a governor head speed up to 50000; an invalid value names its function and value in the refusal.
  - A reconnected link refuses steps until its flight-controller identity is known. A different controller ends a suspended read/return job and permits its own ground read. The post-flight list survives an in-air interlock cycle or widget interruption, and the ground model-status line follows repaired setup faults. Session timestamps display as `YYYY-MM-DD HH:MM` while retaining SD compatibility.
