- **The tool asks for the save notice's progress only when it may have changed (`tasks/msp/save_pipeline.lua`, `ui/home.lua`)**:
  - While a save notice was on screen, every run of the tool asked the save pipeline for its progress, which builds a new table on every call (568 bytes on desktop Lua 5.3, 64-bit), only to find that nothing it draws had changed. A failed outcome stays until it is dismissed, so this went on for as long as the notice was read. The pipeline now keeps a revision number, raised wherever anything `getProgress()` reports changes, and the tool asks for the table only when that number moved; the comparison that decides a repaint is unchanged. Measured on desktop Lua 5.3, a run with an unchanged notice allocates nothing instead of 568 bytes and costs 34 instructions instead of 78 (failed outcome) or 84 instead of 161 (write in progress); with no save it costs 31 instead of 37. `getProgress()` still returns a new table on every call (#771).
