- **In-flight tuning: one press is one step however slowly the widget runs (`widgets/dashboard/inflight/setup.lua`, `widgets/dashboard/inflight/drive.lua`, `app/pages/settings/dashboard/inflight/page.lua`, `docs/pages/settings/dashboard/inflight.md`, `docs/dashboard/inflight-tuning.md`)**:
  - The pulse on the value channel was ended by the widget, on the first pass at or after its length. With the tuning surface up a colour radio can run that pass at about 300 ms, which is where the flight controller takes its second step, so a single press could step a parameter twice. *Set up the model* now switches the value line with a logical switch, `|GVx| > 0` with a delay of 0.1 s and a duration of 0.2 s, and the radio's mixer ends every plateau after 200 ms, whatever the widget pass does. It takes a slot that already holds that switch or the last empty logical switch nothing on the model refers to, names it in its confirmation, and refuses rather than writing over a slot that holds anything else.
  - A model set up by an earlier version has a value line without that switch; the setup check reports *Mixer line missing or wrong* and the interlock stays refused until *Set up the model* has run once more.
  - The *Pulse length* setting is gone; the value variable stands a fixed 310 ms per press, long enough for the logical switch's window to run out in full; a value stored by an earlier version is ignored.
  - A held step control repeats by pulsing again after each pulse and a 150 ms gap, about two steps a second and each pulse exactly one step, instead of leaving the value standing for the flight controller's own 200 ms repeat. While a control is held, a bank chip and the walk and bank trims wait for it to be let go.
