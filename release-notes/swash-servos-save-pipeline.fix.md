- **Swash Geometry and both Servos pages save through the shared save, so a save the page is left during writes everything Save was pressed with, and a refused write is reported (`app/pages/setup/mixer/swashgeometry/page.lua`, `app/pages/setup/servos/pwm/page.lua`, `app/pages/setup/servos/bus/page.lua`, `docs/reference/saving.md`)**:
  - The writes and the EEPROM write go through the shared save (`tasks/msp/save_pipeline.lua`), every payload built when Save is pressed, instead of a chain the page queued from its own replies. On Swash Geometry a page closed before the chain had finished no longer leaves the mixer configuration changed on the flight controller and the three mixer inputs unsent and nothing stored; on PWM and BUS Output the EEPROM write's reply no longer runs against the state the page's close released (#574).
  - The save's progress and outcome are shown in the shared save notice: *Settings saved.* once the flight controller has stored the values, *Not saved* when a write or the EEPROM write was refused or not answered. Before, these pages said *Saved* as soon as the write was queued, whatever the flight controller answered (#594). Back pressed during the save steps back to the menu, and the page is released once the notice has gone.
