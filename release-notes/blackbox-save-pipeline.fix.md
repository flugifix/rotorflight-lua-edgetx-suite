- **Blackbox Configuration and Logging save through the shared save, so a save the page is left during sends what Save was pressed with (`app/pages/setup/controls/blackbox/configuration/page.lua`, `app/pages/setup/controls/blackbox/logging/page.lua`, `docs/reference/saving.md`)**:
  - The writes and the EEPROM write go through the shared save (`tasks/msp/save_pipeline.lua`), each payload built when Save is pressed, instead of a chain the page queued from its own replies. On Configuration a page closed before the first write was answered no longer drops the debug settings write, and a page opened again at once no longer sends that visit's debug settings in place of the saved ones. A reply after the close no longer runs the page's read against the state its close released (`attempt to index a nil value (field 'runtime')`, which the MSP queue catches and logs as a warning) (#574).
  - Both pages end their read when they are left before it is answered, instead of queuing the next read of the chain after the page has gone; on Logging that read's reply raised (`attempt to index a nil value (upvalue 'BlackboxConfigApi')`), and on Configuration a visit opened again at once could refuse Save until Reload (#574).
  - The save's progress and outcome are shown in the shared save notice, so a failed write now reports *Not saved* instead of nothing; a debug settings write the flight controller refuses fails the save before the EEPROM write. Back pressed during the save is not asked about unsaved changes; the page is left once the notice has gone. After a save that worked, the page reads the flight controller again while it is still open.
