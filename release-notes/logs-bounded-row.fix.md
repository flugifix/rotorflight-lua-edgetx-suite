- **A log row with no line end is no longer collected without a limit (`lib/flight_log.lua`, `app/pages/logs/graph.lua`, `app/pages/tools/flight_log/page.lua`, `docs/pages/tools/flight_log.md`)**:
  - Both CSV readers now give up a row they are still collecting once it holds more than 1024 bytes and another chunk is needed, and skip to the next line end, writing one debug line for it. Before, the unfinished row was joined to every new 4 KiB chunk: on desktop Lua 5.3 a 256 KiB file without a line end allocated 17.3 MB in the flight log reader and over the graph's walk, and a valid telemetry header followed by one such row 11.4 MB in a single tick of the graph's scan; now 0.26 MB in each reader and 0.13 MB in that tick, about the bytes read. The flight log reader also counts a chunk read against its per-call line budget, so one call reads at most that many chunks however the file is made; before, one call read the whole of such a file. The graph already refused a complete line over 1024 bytes and feeds exactly the lines it fed before. The flight log reader had no bound at all: a complete line of any length is still parsed, and a line over 1024 bytes is now skipped only where that much of it is pending when the next chunk is read (#769).
