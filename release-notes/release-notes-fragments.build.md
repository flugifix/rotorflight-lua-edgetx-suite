- **Release notes are written as one file per pull request under `release-notes/` and filed under their release when it is cut (`release-notes/README.md`, `bin/release/collect_release_notes.py`, `bin/release/verify_release_notes_rule.py`, `.github/workflows/pr.yml`, `.github/workflows/checks.yml`, `.github/workflows/release.yml`, `.github/workflows/snapshot.yml`, `GEMINI.md`, `.agents/rules/release_notes.md`, `DEVELOPMENT.md`, `docs/developer/audio-announcements.md`, `docs/developer/dashboard-themes.md`)**:
  - A pull request adds `release-notes/<short-name>.<feature|fix|build>.md` instead of editing `Releases.md`. The file names no version, so a pull request that waits past a version bump no longer carries its entry under the release before, and two open pull requests no longer collide in `Releases.md`.
  - `bin/release/collect_release_notes.py` files the pending notes under the version in `version.lua` at release time, adds the pull request number from the merge commit (squash or merge), and deletes the files. A `release/*` or `snapshot/*` tag with pending notes stops before anything is built.
  - A new *Release notes rule* job asks a pull request that changes `src/` for a note or a `Release notes:` line in its body, the same shape as the documentation rule. Editing `Releases.md` directly still passes, so pull requests opened before this are not stopped.
