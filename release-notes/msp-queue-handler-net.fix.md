- **Raising MSP handlers no longer hold the request queue (`tasks/msp/queue.lua`)**:
  - A reply handler (`processReply`, on the cache, simulator and wire paths) or a give-up `errorHandler` that raises no longer keeps its message current: the message is released and the error is logged as a warning. An answered request is not sent again, a message is given up once, and the queue moves on to what is queued behind it. A handler stopped at EdgeTX's instruction limit is the exception and behaves as before: the stop leaves the call, and the message stays current and is handled again on a later pass. A handler that returns normally sees no change (#797, #574).
