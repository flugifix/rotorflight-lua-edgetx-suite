- **Card logs are grouped by power-up and carry the memory figures (`lib/log_sink.lua`, `lib/log.lua`, `app/pages/developer/developer_settings/page.lua`, `docs/troubleshooting/collecting-logs.md`)**:
  - Every file of one power-up of the radio is named after the moment it was switched on (`2026-10-29_10-15-03_dashboard.log`, `..._tool.log`, `..._function.log`, each with a `.step` beside it), so the files that belong together sort next to each other; the configuration tool opened again in the same power-up adds to its file. The rotating `_1` … `_10` slots and the `_seq.txt` counters are gone.
  - The header line of every session also names the date and time, the build identity and the language.
  - Every five seconds the dashboard, the configuration tool and the background decoder write a state line with their Lua memory and the radio's free memory, and on EdgeTX 2.12.5 and later the CPU load and the screen's frame rate (#815). The configuration tool being opened and closed, the in-flight tuning surface changing phase or closing, and page changes carry the same figures.
  - *Developer* → *Settings*: *Debug Level* is now called *Log Level*; *Continuous Memory Log* is removed, the state line replaces it; new *Keep Logs Of* sets how many power-ups keep their files (default 10). Every row has its own `?`.
  - Requests to and replies from the flight controller are logged at *TRACE* instead of *DEBUG*; a request sent again is still logged at *DEBUG*.
  - Fixed: a tool opened from the dashboard no longer turns the dashboard's log files into `tool` files, the step file is no longer rewritten on every call when two kinds of step alternate, and the card write no longer lands on a pass that has just built a page (#608).
