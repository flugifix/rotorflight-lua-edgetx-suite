- **Stats and both Beepers pages save through the shared save, so a reply after the page is closed no longer reaches what its close released (`app/pages/setup/controls/stats/page.lua`, `app/pages/setup/controls/beepers/configuration/page.lua`, `app/pages/setup/controls/beepers/dshot/page.lua`, `docs/reference/saving.md`)**:
  - The write and its EEPROM write go through the shared save (`tasks/msp/save_pipeline.lua`) instead of a chain the page queued from its own replies. A reply that arrives after the page was closed during the save no longer runs the page's read against the state its close released (`attempt to index a nil value (field 'runtime')`, which the MSP queue catches and logs as a warning) (#574).
  - The save's progress and outcome are shown in the shared save notice, so a failed write now reports *Not saved* instead of nothing. Back pressed during the save is not asked about unsaved changes; the page is left once the notice has gone. After a save that worked, the page reads the flight controller again while it is still open; on Stats the flight count kept for the flight record is set from the saved value also when the page was closed.
