- **Stats and both Beepers pages finish their save when they are left while it is running (`app/pages/setup/controls/stats/page.lua`, `app/pages/setup/controls/beepers/configuration/page.lua`, `app/pages/setup/controls/beepers/dshot/page.lua`, `docs/reference/saving.md`)**:
  - The write and its EEPROM write go through the shared save (`tasks/msp/save_pipeline.lua`) instead of a chain the page queued from its own replies, so the save completes without the page. A reply that arrives after Back, Menu or the tool opened from the dashboard closing no longer runs the page's code against the state its close released (`attempt to index a nil value (field 'runtime')`, which the MSP queue catches and logs as a warning) (#574).
  - The save's progress and outcome are shown in the shared save notice, so a failed write now reports *Not saved* instead of nothing. The page reads the flight controller again after the save while it is still open; on Stats the flight count the flight record counts from follows the saved value also when the page was left.
