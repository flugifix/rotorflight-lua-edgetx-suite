- **The dashboard's connection check reads the startup progress without building a table (`tasks/msp/runtime.lua`, `widgets/dashboard/runtime.lua`)**:
  - `updateConnectionState` asks the MSP runtime on every logic tick (ten a second, twenty while a start is in progress) whether the startup reads are done, and `Runtime.getProgress()` answered with a new four-field table each time, of which the dashboard read two fields. The new `Runtime.getProgressValues()` returns the same four values as plain results (`done, total, active, queueIdle`) and the dashboard calls it; measured on desktop Lua 5.3, the dashboard's read allocates 0 bytes per tick instead of 184. `getProgress()` stays, as a wrapper that returns the same values in a new table on every call, for the tool's start screen. The values are identical for every runtime and queue state, so startup and reconnect behave as before (#763).
