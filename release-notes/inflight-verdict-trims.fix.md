- **In-flight tuning: the setup check sees the trims before the first closing, in every flight mode (`widgets/dashboard/inflight/drive.lua`, `widgets/dashboard/inflight/setup.lua`, `settings/dashboard/inflight`, `docs/dashboard/inflight-tuning.md`)**:
  - The trims are now looked up on the ground when the interlock is closed, and the closing is refused with *SETUP: Checking trims* until that is done. Before, the first closing after every start was checked without them, so a trim stored as a switch position that still trimmed passed, and only the next closing refused it (#585).
  - The trim half of the check holds every flight mode, following EdgeTX's link from a flight mode to the one whose trim it uses, instead of the active flight mode alone. A mode with a trim of its own no longer passes on the ground and trims in the air, and a mode that follows a mode whose trim is off is no longer reported. *Set up the model* judges the modes the same way and leaves such a linked mode as it is. The fault now reads *Trim still active* on the dashboard and *Trim still active in a flight mode* on the settings page.
